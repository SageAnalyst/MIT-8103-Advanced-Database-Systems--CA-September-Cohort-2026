QUERY 1: MULTI-CHANNEL OUTREACH CONVERSION AND SALES PERFORMANCE




Target SQL Statement:
SELECT 
    O.Outreach, 
    COUNT(S.collection_id) AS Total_order, 
    SUM(S.quantity_sold) AS Total_sales,
    ROUND(SUM(S.quantity_sold) / COUNT(O.collection_id), 2) AS Conversion_rate
FROM Outreach O
JOIN sales S 
    ON S.collection_id = O.collection_id
GROUP BY O.Outreach;

    -> Aggregate using temporary table

            -> Table scan on O  (cost=3.95 rows=37) (actual time=0.014..0.021 rows=37 loops=1)
            -> Filter: (S.collection_id = O.collection_id)  (cost=0.93 rows=4) (actual time=0.001..0.001 rows=4 loops=37)
                -> Index lookup on S using PRIMARY (collection_id=O.collection_id)  (cost=0.93 rows=4) (actual time=0.001..0.001 rows=4 loops=37)


Planning Time: 0.284 ms
Execution Time: 0.112 ms


Bottleneck Diagnostics:
- Access Type on O: Full Table Scan (ALL) across the Outreach relation.
- Grouping Mechanism: "Using temporary; Using filesort" - the database engine constructs an internal temporary table in memory/disk to evaluate grouping across the unindexed VARCHAR column `O.Outreach`.
- High join buffer iteration during hash/nested loop join resolution.
